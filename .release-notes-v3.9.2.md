## snapgentV3 V3.9.2

This patch release fixes the bridge hanging after a large MCP response. On macOS (and any setup with big folders), `list_dir` or `read_files` could make the MCP server appear disconnected, and every later request then timed out.

### Fixed
- **Bridge stops responding after a large MCP response.** asyncio limits each line read from an MCP server to 64 KB. A single large response (for example `read_files` or `list_dir` on a big folder such as a home directory) made the stdout reader fail while the server process stayed alive, so the bridge never restarted it and every later request timed out. The stream limit is now 64 MB, a dead reader now counts as a dead server so it is restarted automatically, and the cause is written to the log.

### Tests
- Added a regression test that sends a 200 KB response line through the bridge.

### Changed
- Extension version bumped to **3.9.2**.

### Upgrade
Pull the latest `main` and restart the bridge. No extension reload is needed for the bridge fix itself.
