## snapgentV3 V3.9.3

This release makes versions visible, so it is easy to tell whether the bridge was updated after pulling a fix. This matters for V3.9.2, whose bridge fix only takes effect after the bridge is restarted.

### Added
- **Bridge version is now visible.** The bridge defines `BRIDGE_VERSION`, writes it to the startup log (`snapgent bridge v...`), sends it to the extension in the `connected` message, and reports it as the MCP `clientInfo` version instead of the fixed `1.0.0`.
- **Versions in the popup header.** The popup shows `ext vX · bridge vY`. If the bridge is too old to report a version, it shows `bridge old`, which means the bridge was not updated and restarted after pulling.

### Changed
- Extension version bumped to **3.9.3**.
- The release badge, install link and footer in `README.md` now point to V3.9.3.

### Known limitation (Windows)
`start.bat` runs the bundled `bridge.exe`, which was last rebuilt on 2026-10-23. It does not yet include the V3.9.2 fix for large MCP responses or the version display, so on Windows the popup shows `bridge old`. Until `bridge.exe` is rebuilt, run the current bridge with Python 3.9+: `py -3 -m pip install websockets`, close `start.bat`, then run `py -3 bridge.py` in the project folder. macOS and Linux already use `bridge.py` and are not affected.

### Upgrade
Pull the latest `main`, restart the bridge, then reload the extension at `chrome://extensions` (or `edge://extensions`) and refresh open chat tabs (F5).
