## snapgentV3 V3.9.7

This release raises the bridge's capacity for large payloads and makes it more stable under load. The bridge version now matches the release (it was stuck at 3.9.4).

### Changed
- **Bridge: large-payload capacity.** MCP stdout buffer 64 MB -> 128 MB. An oversized MCP response line no longer kills the server: the waiting request fails with a clear error and the server stays alive. WebSocket `max_size` 50 MB -> 128 MB, `max_queue=256`, `ping_timeout` 20 s -> 90 s.
- **Bridge: concurrent requests** (up to 32), so one slow tool call no longer blocks pings. JSON over 256 KB is parsed and serialized in a worker thread, and the Roblox process check no longer blocks the event loop.
- **Bridge: restart with backoff.** A failed MCP server is retried with a growing delay (up to 300 s) and logs `restarting (attempt N)`.
- **Bridge: errors are logged.** Send failures are logged and handler errors are returned to the extension as `Bridge error`.
- Extension: `STALE_SOCKET_MS` 25 s -> 60 s (still below the bridge `ping_timeout`) to avoid false reconnects on very large frames.
- Extension: target dropdown uses the display name, Roblox shows a tool count fallback, and the MCP popup's Background sessions row is simplified.
- Bridge version bumped to **3.9.7**. `bridge.exe` is rebuilt and attached to this release.

### Added
- Three regression tests in `test_bridge.py` (ping during a slow call, large tool result over WebSocket, oversized MCP line).

### Upgrade
Download `bridge.exe` from the assets below and replace the one next to `start.bat`. Keep your own `config.json`. Reload the extension at `chrome://extensions` (or `edge://extensions`) and refresh open chat tabs (F5). Restart the bridge so the window shows `snapgent bridge v3.9.7`.
