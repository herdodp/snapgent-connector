## snapgentV3 V3.9.9

This release makes a "bridge offline" report traceable. Before the extension tells the model the bridge is offline, it now records why. The same release also fixes one cause of Background sessions not working in a hidden tab. The logging change only adds diagnostics. The bridge is unchanged (still 3.9.7), so `bridge.exe` does not need to be rebuilt.

### Fixed
- **Background sessions now keep working in a hidden tab.** With the setting on, the reply-wait loop still parked a hidden tab: it re-entered the park step every 400 ms and never read the reply, so the session looked stalled until you returned to the tab. The park step now respects the setting. With the setting off, behavior is unchanged.

### Changed
- **The "bridge offline" verdict is now traceable.** Every failure path (socket closed, never opened, worker gave no answer) used to end in the same message, so an "unreachable while the bridge is open" report could not be traced. The extension now records a `bridge.offlineVerdict` diagnostic with the command name, plus the error and sent state of the first attempt and of the retry.
- Extension and Snapgent App versions bumped to **3.9.9**.

### Upgrade
Reload the extension at `chrome://extensions` (or `edge://extensions`) and refresh open chat tabs (F5) so the popup shows `ext v3.9.9`. The bridge is unchanged, so keep your current `bridge.exe`.

The attached zip contains everything needed to run: the extension, `bridge.exe`, `vscode_mcp.exe`, the start scripts (`start.bat`, `MacOS_Start.command`, `Linux_Start.sh`), the Python sources and the README. Extract it, load the `snapgent-extension` folder, and run the start script for your system.
