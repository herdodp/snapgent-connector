## snapgentV3 V3.9.12

Starting the Snapgent bridge no longer opens FigCraft or EffectCraft automatically. Each app can
now be opened on demand with its Snapgent helper, so the bridge can start independently and users
can choose when to launch the GUI. This release also closes a local-only progress endpoint and
makes the launchers install the dependency the live view needs.

The bridge-side changes below ship **in `bridge.py` only**: the bundled `bridge.exe` was **not
rebuilt** for this release, so Windows users who run the executable keep the previous behaviour
until a rebuild is published.

### Changed
- Added dedicated Windows and macOS/Linux helpers for opening FigCraft and EffectCraft with their
  MCP control channels.
- FigCraft's helper reuses a detected control port or selects an available loopback port.
- Normal bridge startup detects an existing FigCraft control channel without launching the app.
  EffectCraft and FigCraft sessions already open without a control channel are not closed or
  restarted.
- Restart the Snapgent bridge after opening either app so its MCP configuration connects.
- Extension and Snapgent App versions bumped to **3.9.12**. The bridge source is unchanged in
  version terms (still 3.9.7), so `bridge.exe` does not need to be rebuilt.
- **The progress channel is read-only.** `POST /push` is removed. It was added in the previous
  change, nothing in the extension used it (progress travels over the WebSocket `stream`
  message), and any local page could POST a frame into the live view.
- **Launchers install `aiohttp`.** `Linux_Start.sh` and `MacOS_Start.command` install `websockets`
  and `aiohttp` together with the same pip/venv fallback. Without `aiohttp` the bridge now prints
  a visible warning and disables the live view instead of only writing a log line.
- **`BRIDGE_VERSION` bumped to 3.9.12**, matching the extension manifest so the version shown in
  the popup is meaningful again.
- README documents the live view (`http://127.0.0.1:17614/`), the stream port, and the **Remote
  commands** opt-in together with its risk.

### Security
- **WebSocket origin check.** The bridge handshake now rejects any `Origin` that is not a
  browser-extension URL (`chrome-extension://`, `moz-extension://`, `safari-web-extension://`)
  with HTTP 403, and `handle_client` repeats the check and closes the socket (code 1008) as a
  second layer. A page on any website can no longer open `ws://127.0.0.1:17613` and run tools
  such as `run_command` or `write_file`. Clients without an `Origin` header (command-line tools,
  tests, native apps) still work; custom front ends can be listed in `ZS_BRIDGE_EXTRA_ORIGINS`
  (comma separated).

### Who gets the bridge-side changes
- **`bridge.py` users** (macOS and Linux launchers, and Windows when starting from source): yes.
  Pull the release, restart the bridge, and the launcher installs `aiohttp`. The stream channel
  then serves `/`, `/events`, `/stream` and `/status`, and `POST /push` returns 404.
- **`bridge.exe` users** (the Windows default through `start.bat`): no. The executable is not
  rebuilt in this release, so it keeps the bridge code it was built with. Rebuilding it needs
  PyInstaller with `--hidden-import aiohttp` so the live view dependency is bundled; that rebuild
  has not been done yet.
- **Extension-only fixes** are unaffected: they ship in the extension folder and need a reload,
  not a bridge restart.

### Upgrade
Reload the extension at `chrome://extensions` (or `edge://extensions`) and refresh open chat tabs
(F5) so the popup shows `ext v3.9.12`. Restart the bridge with `MacOS_Start.command` or
`Linux_Start.sh` so the launcher installs `websockets` and `aiohttp` and `bridge.py` 3.9.12 runs.

Run `Open-FigCraft-for-Snapgent.bat` or `Open-EffectCraft-for-Snapgent.bat` on Windows, or the
corresponding `open-*-for-snapgent.sh` helper on macOS/Linux when you want to open either app.
Restart the normal Snapgent bridge launcher afterward.

On Windows running from source (`start.bat` starts the bundled executable; use `py -3 bridge.py`
for source), install the dependencies once:

```
py -3 -m pip install --user websockets aiohttp
```

The attached zip contains everything needed to run: the extension, `bridge.exe`, `vscode_mcp.exe`,
the start scripts (`start.bat`, `MacOS_Start.command`, `Linux_Start.sh`), the setup scripts, the
manual app launchers, the Python sources and the README. Extract it, load the `snapgent-extension`
folder, and run the start script for your system.
