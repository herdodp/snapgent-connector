## snapgentV3 V3.9.12

Starting the Snapgent bridge no longer opens FigCraft or EffectCraft automatically. Each app
can now be opened on demand with its Snapgent helper, so the bridge can start independently
and users can choose when to launch the GUI.

### Changed
- Added dedicated Windows and macOS/Linux helpers for opening FigCraft and EffectCraft with
  their MCP control channels.
- FigCraft's helper reuses a detected control port or selects an available loopback port.
- Normal bridge startup detects an existing FigCraft control channel without launching the
  app. EffectCraft and FigCraft sessions already open without a control channel are not
  closed or restarted.
- Restart the Snapgent bridge after opening either app so its MCP configuration connects.
- Extension and Snapgent App versions bumped to **3.9.12**. The bridge is unchanged (still
  3.9.7), so `bridge.exe` does not need to be rebuilt.

### Upgrade
Reload the extension at `chrome://extensions` (or `edge://extensions`) and refresh open chat
tabs. Run `Open-FigCraft-for-Snapgent.bat` or `Open-EffectCraft-for-Snapgent.bat` on Windows,
or the corresponding `open-*-for-snapgent.sh` helper on macOS/Linux when you want to open
either app. Restart the normal Snapgent bridge launcher afterward.

The attached zip contains the extension, bridge, MCP server, setup scripts, manual app
launchers, Python sources and README. Extract it, load the `snapgent-extension` folder, and
run the start script for your system.
